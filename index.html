Overview

The platform helps instructors and integrity officers answer two questions about a student text: does it reuse text from known sources, and is its writing style consistent with the claimed author. It was built in the research project Advancing Plagiarism Detection through Contextual Embeddings at SDU NLP, SDU University. See About the project.

It has three parts:

  • This website. A similarity check and a style comparison that run in the browser with baseline methods. Use it for quick checks and for teaching what the scores mean.
  • The API server. A small HTTP service that scores texts with a contextual embedding model. This is the part that detects paraphrased passages. Other systems call it.
  • The Moodle plugin. Sends each assignment submission to the API server and shows the result to the teacher in the grading view. Other platforms can call the API in the same way.

Обзор

Платформа помогает преподавателям и специалистам по академической честности ответить на два вопроса о студенческом тексте: повторяет ли он текст известных источников и соответствует ли его стиль письма заявленному автору. Она создана в исследовательском проекте Advancing Plagiarism Detection through Contextual Embeddings группой SDU NLP, SDU University. См. раздел «О проекте».

Платформа состоит из трёх частей:

  • Этот сайт. Проверка сходства и сравнение стиля, которые выполняются в браузере базовыми методами. Подходит для быстрых проверок и для объяснения того, что означают показатели.
  • Сервер API. Небольшая HTTP-служба, которая оценивает тексты с помощью модели контекстных эмбеддингов. Именно она находит пересказанные фрагменты. К ней обращаются другие системы.
  • Плагин для Moodle. Отправляет каждую сданную работу на сервер API и показывает результат преподавателю на странице оценивания. Другие платформы могут обращаться к API таким же образом.

Quick start for instructors

  1. Open Similarity check. Paste the student text into Submission, or load a file.
  2. Paste each reference text into a Source box and give it a short name. Use Add a source for more.
  3. Select Run check. Read the matched-text share first, then the per-source table, then the highlighted passages. Each highlight carries the number of its source.
  4. Use Copy, Download .txt or Print or save PDF to keep the report for a case file.
  5. To detect paraphrase, open Connect to the project API, enter your institution's API address and key, and select Test connection. Later checks add a sentence-level comparison by meaning.
  6. For a style question, open Authorship, paste the questioned text, add earlier work by the student and by at least one other writer, and select Compare style.

You can load .txt, .docx and text-based .pdf files. Scanned PDFs have no text layer and need OCR first. Texts may be in any language written with spaces between words, including Kazakh, Russian and English. The function-word feature in the style comparison covers English, Russian and Kazakh and is skipped for other languages.

If your institution uses Moodle with the project's plugin, you do not need this website for routine checks: the result appears beside each submission in the grading view.

Краткое руководство для преподавателей

  1. Откройте «Проверку сходства». Вставьте текст студента в поле «Работа» или загрузите файл.
  2. Вставьте каждый текст для сравнения в поле «Источник» и дайте ему короткое название. Чтобы добавить ещё, нажмите «Добавить источник».
  3. Нажмите «Проверить». Сначала посмотрите долю совпавшего текста, затем таблицу по источникам, затем выделенные фрагменты. Рядом с каждым выделением стоит номер источника.
  4. Кнопки «Копировать», «Скачать .txt» и «Печать или PDF» позволяют сохранить отчёт в материалах дела.
  5. Чтобы находить пересказ, откройте «Подключиться к API проекта», введите адрес и ключ API вашего учебного заведения и нажмите «Проверить подключение». После этого к каждой проверке добавляется сравнение предложений по смыслу.
  6. Если вопрос касается стиля, откройте «Авторство», вставьте спорный текст, добавьте прежние работы студента и хотя бы одного другого автора и нажмите «Сравнить стиль».

Можно загружать файлы .txt, .docx и .pdf с текстовым слоем. В сканированных PDF текстового слоя нет, их нужно сначала распознать (OCR). Тексты могут быть на любом языке, где слова разделяются пробелами, включая казахский, русский и английский. Признак «служебные слова» при сравнении стиля рассчитан на английский, русский и казахский языки и для других языков не используется.

Если в вашем учебном заведении работает Moodle с плагином проекта, для обычных проверок этот сайт не нужен: результат показывается рядом с каждой работой на странице оценивания.

Оқытушыларға арналған қысқаша нұсқаулық

  1. «Ұқсастықты тексеру» бетін ашыңыз. Студент мәтінін «Жұмыс» өрісіне қойыңыз немесе файл жүктеңіз.
  2. Салыстырылатын әрбір мәтінді «Дереккөз» өрісіне қойып, оған қысқа атау беріңіз. Тағы қосу үшін «Дереккөз қосу» түймесін басыңыз.
  3. «Тексеру» түймесін басыңыз. Алдымен сәйкес келген мәтіннің үлесін, содан кейін дереккөздер кестесін, соңында белгіленген үзінділерді қараңыз. Әр белгінің жанында дереккөздің нөмірі тұрады.
  4. Есепті іс материалдарында сақтау үшін «Көшіру», «.txt жүктеп алу» немесе «Басып шығару немесе PDF» түймелерін қолданыңыз.
  5. Қайта баяндалған мәтінді табу үшін «Жоба API-іне қосылу» бөлімін ашып, оқу орныңыздың API мекенжайы мен кілтін енгізіңіз де, «Қосылуды тексеру» түймесін басыңыз. Бұдан кейін әр тексеруге сөйлемдерді мағынасы бойынша салыстыру қосылады.
  6. Стильге қатысты сұрақ болса, «Авторлық» бетін ашып, күмәнді мәтінді қойыңыз, студенттің бұрынғы жұмыстарын және кем дегенде тағы бір автордың жұмысын қосыңыз да, «Стильді салыстыру» түймесін басыңыз.

.txt, .docx және мәтін қабаты бар .pdf файлдарын жүктеуге болады. Сканерленген PDF файлдарында мәтін қабаты болмайды, оларды алдымен тану (OCR) қажет. Мәтіндер сөздері бос орынмен бөлінетін кез келген тілде, соның ішінде қазақ, орыс және ағылшын тілдерінде бола алады. Стильді салыстырудағы «көмекші сөздер» белгісі ағылшын, орыс және қазақ тілдеріне есептелген, басқа тілдерде қолданылмайды.

Оқу орныңызда жобаның плагині орнатылған Moodle жұмыс істесе, күнделікті тексеру үшін бұл сайттың қажеті жоқ: нәтиже бағалау бетінде әр жұмыстың жанында көрсетіледі.

How to read the scores

ScoreWhat it measuresWhere
Matched textShare of the submission's words that sit inside a word sequence (three words by default) also found in a source. Catches copied and lightly edited text.Website, API (containment), Moodle report
JaccardShared three-word sequences divided by all three-word sequences in both texts. Low when the texts differ a lot in length.Website, API, Moodle report
Term cosineCosine between the word-count vectors of the two texts. High for texts on the same topic, even with no copying.Website
Longest runLongest unbroken stretch of matched words.Website
Flagged shareShare of submission sentences whose embedding has a cosine at or above the threshold with some source sentence. Catches paraphrase.API, Moodle
Style similarityCombined closeness of two texts in character trigrams, function words and sentence and punctuation habits.Website

The website labels matched text below 15% as low, 15% to 40% as moderate and above 40% as high. These bands are a reading aid. Correctly quoted and cited passages also count as matches, so a reviewer always has to look at the highlighted text before drawing a conclusion.

Method

This section is available in English only.

Lexical baselines

Texts are lower-cased and split into words. Every run of three consecutive words is a shingle. The website lets you raise this to four or five words to ignore short chance matches. Jaccard and matched-text share are computed from the two shingle sets. Term cosine uses raw word counts.

Contextual embeddings

The API splits each text into sentences and encodes every sentence with a transformer sentence encoder. Vectors are normalised, so the dot product of two vectors is their cosine similarity:

cos(a, b) = (a · b) / (‖a‖ ‖b‖)

For each submission sentence the API finds the most similar source sentence. A pair at or above the threshold (default 0.80) is returned as a match. Because the encoder represents meaning in context, a reworded sentence still lands close to its original, where the shingle methods see nothing. The second example source on the check page shows this gap: it is a paraphrase and gets a low lexical score.

Encoders read a limited number of tokens and silently ignore the rest. The API therefore cuts any sentence longer than 60 words into consecutive parts, so that lists, tables and unpunctuated text are compared in full.

Style comparison

On the website, style similarity is a weighted mean of character-trigram cosine (0.5), function-word cosine (0.3) and closeness of seven scalar habits such as mean sentence length and commas per 100 words (0.2). On the API, each author is represented by the mean embedding of their sentences and candidates are ranked by cosine to the questioned text.

Integration with learning platforms

This section is available in English only.

The API is stateless, so any platform that can send an HTTP request when a student submits work can use it. The flow is the same everywhere:

  1. Trigger. The platform signals that a submission was created or updated.
  2. Extract. A connector reads the submitted file and converts it to plain text.
  3. Select sources. The connector gathers the comparison texts.
  4. Score. The connector posts the submission and sources to /v1/compare.
  5. Report. The connector stores the response and shows the instructor the flagged share and the matched sentence pairs next to the submission.

Moodle

The repository contains a Moodle plagiarism plugin, plagiarism_sduembed, in integrations/moodle. It needs Moodle 4.1 or later and implements the five steps above for assignments:

  • A teacher switches the check on in the assignment settings. Students see a notice on the submission page.
  • When a student submits a file (.docx, .odt, .txt, .html, and .pdf if pdftotext is installed) or online text, the plugin queues it. A scheduled task sends it to the API every five minutes, so submitting stays fast even when the API is busy or down.
  • Each submission is compared with the latest work of the other students in the same assignment. Earlier submissions are checked again as classmates submit.
  • The grading view shows a line such as “25% of sentences have a close match” beside each submission, with a link to a report of the matched sentence pairs.
  • Only text and numeric submission ids are sent to the API. Names and user ids stay in Moodle. The plugin implements Moodle's privacy API for data export and deletion.
  • The plugin's own interface is available in English, Kazakh and Russian.

Status. The plugin is a beta release. Its request and result-merging code is tested against the API server. It has not yet been run in a pilot course; see About the project for the current state.

Canvas, Blackboard and others

Platforms that support LTI 1.3 can launch an external tool from an assignment. Host a small web application that receives the launch, fetches the submission, calls the API and renders the report. Platforms without LTI can call the API from a nightly script that reads submissions through the platform's own REST API. An LTI tool is planned after the Moodle pilot and is not part of this release.

Installation guide for administrators

This section is available in English only.

An institution installs two things: one API server, and the Moodle plugin that calls it. This website needs no installation. Plan for about an hour.

Before you start

  • A Linux server on the institution's network that the Moodle server can reach. Python 3.9 or later, or Docker.
  • Enough memory for the model. The default multilingual model is roughly half a gigabyte on disk. A GPU is recommended for large classes; a CPU is enough for single documents.
  • A host name and TLS certificate for the API, for example plagiarism.example.edu.kz.
  • Administrator access to Moodle 4.1 or later, with cron running.

Step 1. Start the API server

With Docker:

git clone https://github.com/shiralikadyrov/plagiarism-platform
cd plagiarism-platform
docker build -t plagiarism-api .
openssl rand -hex 24          # use the output as the API key
docker run -d --name plagiarism-api --restart unless-stopped \
  -p 127.0.0.1:8000:8000 -v plagiarism-models:/models \
  -e API_KEY=PASTE_THE_KEY_HERE \
  plagiarism-api

Without Docker:

python3 -m venv venv && . venv/bin/activate
pip install -r requirements.txt
API_KEY=PASTE_THE_KEY_HERE uvicorn server:app --host 127.0.0.1 --port 8000

To serve the project's fine-tuned model, set MODEL_NAME to its folder (with Docker, mount the folder with -v /srv/models/sdu:/models/sdu and set -e MODEL_NAME=/models/sdu). All settings are listed in the API reference. The first request downloads or loads the model and takes longer than later ones.

Step 2. Put it behind HTTPS

The server listens on localhost only. Publish it through a reverse proxy that adds TLS, limits request size and limits request rate. An nginx example:

limit_req_zone $binary_remote_addr zone=plagiarism:10m rate=60r/m;

server {
    listen 443 ssl;
    server_name plagiarism.example.edu.kz;
    ssl_certificate     /etc/ssl/certs/plagiarism.pem;
    ssl_certificate_key /etc/ssl/private/plagiarism.key;

    client_max_body_size 8m;            # the Moodle plugin sends at most about 1.2 million characters

    location / {
        limit_req zone=plagiarism burst=40 nodelay;
        proxy_pass http://127.0.0.1:8000;
        proxy_read_timeout 600s;        # long documents on a CPU take time
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

If only Moodle calls the API, also restrict access to the Moodle server's address with a firewall rule or an nginx allow line.

Step 3. Check that it answers

curl https://plagiarism.example.edu.kz/health
curl -H "X-API-Key: PASTE_THE_KEY_HERE" https://plagiarism.example.edu.kz/v1/ping

The first command returns the model name and threshold. The second returns {"status":"ok"} if the key is right and 401 if it is not.

Step 4. Install the Moodle plugin

  1. Copy the folder integrations/moodle/sduembed from the repository to plagiarism/sduembed in the Moodle code directory, or zip that folder and upload it under Site administration → Plugins → Install plugins.
  2. Open Site administration → Notifications and complete the upgrade.
  3. Switch on Site administration → Advanced features → Enable plagiarism plugins.
  4. Open Site administration → Plugins → Plagiarism → SDU NLP similarity check. Set Enable the plugin to Yes, enter the API address and key, and select Save and test the connection.
  5. To check PDF files, install Poppler (apt install poppler-utils) and enter the path to pdftotext.
  6. Ask a teacher to set Check submissions for similarity to Yes in one assignment, submit two test essays as two test students, wait for cron, and open the grading view.

The plugin's README explains every setting, the status messages, and what data is sent and stored.

Step 5. Let this website use your server (optional)

Instructors can then paste texts on the Similarity check page and get the paraphrase check from your server. Start the server with CORS_ORIGINS=https://shiralikadyrov.github.io and give instructors the address and a key. Browsers block calls from an https page to a plain http server, so this needs step 2.

API reference

This section is available in English only.

The reference server is one Python file, server.py, built with FastAPI. All requests and responses are JSON in UTF-8. A running server also serves interactive documentation at /docs.

GET/health

Returns the server status and version, the loaded model names, the threshold, whether a key is required, and the size limits. Needs no key.

GET/v1/ping

Returns {"status":"ok"} if the X-API-Key header is accepted. Connectors use it to test their settings without sending text.

POST/v1/compare

Compares one submission with 1 to 50 sources. threshold is optional. Each text may be up to 200,000 characters.

curl -X POST http://localhost:8000/v1/compare \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_KEY" \
  -d '{
    "submission": "Text of the student work ...",
    "sources": [
      {"id": "library-0142", "text": "Text of a reference document ..."}
    ],
    "threshold": 0.8
  }'
{
  "model": "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2",
  "threshold": 0.8,
  "submission_sentences": 12,
  "overall_flagged_share": 0.25,
  "sources": [
    {
      "source_id": "library-0142",
      "lexical":  {"jaccard": 0.0412, "containment": 0.1037},
      "semantic": {"mean_best_cosine": 0.6121, "flagged_share": 0.25},
      "matches": [
        {"submission_sentence": "...", "source_sentence": "...", "cosine": 0.9134}
      ]
    }
  ]
}

The numbers above show the response shape. They are not measured results.

POST/v1/authorship

Ranks 1 to 50 candidate authors by style similarity to a questioned text. Each candidate has 1 to 50 samples.

{
  "questioned": "Text whose authorship is in question ...",
  "candidates": [
    {"id": "student-17", "samples": ["Earlier essay ...", "Another essay ..."]},
    {"id": "student-23", "samples": ["Earlier essay ..."]}
  ]
}
{
  "model": "...",
  "questioned_sentences": 9,
  "ranking": [
    {"candidate_id": "student-17", "sentences": 31, "style_cosine": 0.8420},
    {"candidate_id": "student-23", "sentences": 14, "style_cosine": 0.7015}
  ]
}

Errors

  • 401: the X-API-Key header is missing or wrong.
  • 422: the body is malformed, a text exceeds 200,000 characters, there are more than 50 sources, or a text has no sentence of three or more words.

Evaluation results

Privacy and responsible use

  • This website processes text in the browser. It sends nothing to a server unless you connect it to an API, and then only to the address you enter. It remembers that address and your language choice on your device and never stores your texts or API key.
  • The reference API server does not write request texts to disk. Institutions that add logging or an archive should tell students and follow their data protection rules.
  • The Moodle plugin sends submission text with numeric submission ids only. It stores the score and the matched sentences in Moodle, and removes them on a data deletion request.
  • Replace student names with pseudonymous identifiers in id fields when you call the API yourself.
  • A score is a prompt for review. Decisions about misconduct belong to people who have read the passages and heard the student.

Конфиденциальность и ответственное использование

  • Этот сайт обрабатывает текст в браузере. Он ничего не отправляет на сервер, пока вы не подключите его к API, и тогда отправляет только по указанному вами адресу. Сайт запоминает на вашем устройстве этот адрес и выбранный язык и никогда не сохраняет ваши тексты и ключ API.
  • Эталонный сервер API не записывает тексты запросов на диск. Учебные заведения, которые добавляют журналирование или архив, должны сообщить об этом студентам и соблюдать свои правила защиты данных.
  • Плагин для Moodle отправляет текст работ только с числовыми идентификаторами работ. Он хранит в Moodle результат и совпавшие предложения и удаляет их по запросу на удаление данных.
  • Если вы обращаетесь к API самостоятельно, заменяйте имена студентов псевдонимными идентификаторами в полях id.
  • Показатель — это повод для проверки. Решение о нарушении принимают люди, которые прочитали фрагменты и выслушали студента.

Құпиялылық және жауапты қолдану

  • Бұл сайт мәтінді браузерде өңдейді. API-ге қоспайынша ол серверге ештеңе жібермейді, ал қосылғаннан кейін тек сіз енгізген мекенжайға жібереді. Сайт сол мекенжайды және таңдалған тілді құрылғыңызда есте сақтайды, ал мәтіндеріңіз бен API кілтін ешқашан сақтамайды.
  • Эталондық API сервері сұраныс мәтіндерін дискіге жазбайды. Журнал жүргізуді немесе мұрағатты қосатын оқу орындары бұл туралы студенттерге хабарлап, деректерді қорғау ережелерін сақтауы керек.
  • Moodle плагині жұмыс мәтінін тек жұмыстың сандық идентификаторымен жібереді. Ол нәтиже мен сәйкес келген сөйлемдерді Moodle-да сақтайды және деректерді жою туралы сұраныс бойынша оларды өшіреді.
  • API-ге өзіңіз жүгінсеңіз, id өрістерінде студенттердің аты-жөнін бүркеншік идентификаторлармен алмастырыңыз.
  • Көрсеткіш — қарап шығуға негіз ғана. Тәртіп бұзу туралы шешімді үзінділерді оқыған және студентті тыңдаған адамдар қабылдайды.

Known limitations

  • The browser checks miss paraphrase and translation. Use the API for those.
  • Short texts give unstable scores. Treat anything under about 150 words with caution.
  • Languages written without spaces between words are not tokenised correctly on this website.
  • Style comparison is affected by topic and genre. Compare texts of the same kind where possible.
  • The check only finds overlap with the sources supplied. It does not search the web. The Moodle plugin compares submissions within one assignment only.
  • The Kazakh and Russian function-word lists and interface translations are awaiting review by native-speaker linguists.

Известные ограничения

  • Проверки в браузере не находят пересказ и перевод. Для этого используйте API.
  • Короткие тексты дают неустойчивые показатели. К текстам короче примерно 150 слов относитесь с осторожностью.
  • Языки, в которых слова не разделяются пробелами, на этом сайте разбиваются на слова неправильно.
  • На сравнение стиля влияют тема и жанр. По возможности сравнивайте тексты одного типа.
  • Проверка находит совпадения только с предоставленными источниками. Поиск в интернете не выполняется. Плагин для Moodle сравнивает работы только в пределах одного задания.
  • Списки служебных слов казахского и русского языков и перевод интерфейса ожидают проверки лингвистами — носителями языка.

Белгілі шектеулер

  • Браузердегі тексерулер қайта баяндауды және аударманы таппайды. Ол үшін API қолданыңыз.
  • Қысқа мәтіндер тұрақсыз көрсеткіштер береді. Шамамен 150 сөзден қысқа мәтіндерге сақтықпен қараңыз.
  • Сөздері бос орынмен бөлінбейтін тілдердегі мәтіндер бұл сайтта сөздерге дұрыс бөлінбейді.
  • Стильді салыстыруға тақырып пен жанр әсер етеді. Мүмкіндігінше бір түрдегі мәтіндерді салыстырыңыз.
  • Тексеру тек берілген дереккөздермен сәйкестікті табады. Интернеттен іздеу жүргізілмейді. Moodle плагині жұмыстарды тек бір тапсырма шегінде салыстырады.
  • Қазақ және орыс тілдерінің көмекші сөздер тізімдері мен интерфейс аудармасы тіл мамандарының тексеруін күтуде.

Research project

Advancing Plagiarism Detection through Contextual Embeddings

This platform is the public output of task 3.3, User-Friendly Integration and Documentation: the project's system made usable inside educational platforms, with open-access documentation.

Host organisation

Research group
SDU NLP
Principal investigator
Shirali Kadyrov, PhD, Professor
Project period
1 January 2024 to 31 December 2026 (36 months)
Funding
Grant funding for scientific and scientific-technical projects.

Goal

To improve plagiarism detection by integrating contextual embeddings from transformer language models, so that a detector understands similarity of meaning and writing style and is not limited to matching identical strings.

Objectives

  • Objective 1. Develop contextual embedding models for a style-based AI detector.
  • Objective 2. Integrate contextual embeddings into plagiarism detection algorithms such as Jaccard and cosine similarity.
  • Objective 3. Validate and optimise the system with an academic corpus, and make it available to educational platforms with open documentation.
